# Checkout Kata — актуальный план ATDD

## Цель

Собрать чек для корзины `🍎 🍎 🍎 🍌 🍌 🍊`.

Действующие правила из примера:

| Товар или правило | Цена |
| --- | ---: |
| `🍎` | `50`; акция «2 за 90» |
| `🍌` | `40` |
| `🍊` | `20` |
| `🍎 + 🍌` | комбо за `70` |

Итоговый чек — строка со следующим содержимым:

```text
🍎 + 🍌 (комбо за 70) 70
🍎 x2 (2 за 90) 90
🍌 x1 40
🍊 x1 20
Итого 220
```

В acceptance-тесте товары передаются как emoji-SKU. Публичный контракт чека:

- `scan(_:)` добавляет товар;
- `receipt: String` возвращает форматированный чек;
- `total: Int` возвращает числовой итог.

## Правила работы

Для каждой маленькой функции соблюдаем цикл:

1. Один изолированный unit-тест становится красным по неверному значению.
2. Останавливаемся для согласования теста.
3. Добавляем только минимальную реализацию, покрытую тестом.
4. Запускаем тот же тест и получаем зелёный результат.
5. Останавливаемся для согласования реализации.
6. После зелёного цикла создаём отдельный Git-коммит.

Acceptance-сценарий проверяет весь пользовательский поток, а unit-тесты —
изолированные части этого потока.

## Состав работы

1. **Корзина.** Хранит количество каждого товара, добавленного сканированием.
2. **Строка чека.** Форматирует обычную цену, спеццену и комбо в заданном
   текстовом виде.
3. **Расчёт правил.** Применяет к содержимому корзины комбо, спеццену и
   обычные цены, формирует строки чека и числовой итог.
4. **Публичный `Checkout`.** Связывает сканирование, корзину и расчёт;
   предоставляет `receipt` и `total`.
5. **Acceptance и финальная проверка.** Полный сценарий проверяет чек и
   итог `220`; после этого запускается весь набор тестов.
6. **Git-история.** Каждый завершённый зелёный TDD-цикл фиксируется отдельным
   коммитом.
